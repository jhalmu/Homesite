## Category: Testing

### Insight: Always Verify Implementation Before Closing Issues
**File**: Multiple GitHub issues #6, #10
**Tags**: #testing #verification #github

**Problem**: GitHub issues were closed for features that weren't actually implemented (User Management UI, Activity Feed).

**Solution**:
Before closing any GitHub issue:
1. Search codebase for expected files/routes
2. Check database for expected tables/schemas
3. Verify functionality actually exists
4. Use git log to find implementation commits
5. Only close if verified

Example verification:
```bash
# Check if route exists
grep -r "/admin/users" lib/homesite_web/router.ex

# Check if module exists
find lib -name "*admin*users*"

# Check if table exists
grep "create table(:activities" priv/repo/migrations/*
```

**Rationale**: GitHub issues should accurately reflect reality. Closing without verification leads to confusion and wasted time in future sessions.

**Why it matters**: This prevented future confusion and ensured project status was accurate. Applied this pattern to audit all open/closed issues today.

## Category: Dependencies

### Insight: GitHub CLI for Issue Management
**File**: MEMO.md session notes
**Tags**: #github #cli #automation

**Problem**: Manual GitHub issue management via web interface is slow and error-prone.

**Solution**:
Use GitHub CLI (gh) for all issue operations:
```bash
# Close with comment
gh issue close 22 --comment "summary"

# Reopen with comment
gh issue reopen 10 --comment "reason"

# Create new issue
gh issue create --title "title" --body "body"
gh issue create --title "title" --body-file file.md

# List all issues
gh issue list --limit 50 --json number,title,state
```

**Rationale**: CLI commands are scriptable, faster, and provide better documentation in MEMO.md. Can be automated in EOD workflow.

**Why it matters**: Sets foundation for automated issue management. All issue operations can now be scripted and integrated into workflows.
